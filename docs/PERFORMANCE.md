# 0.2.0 效率改善

## 已實作

| 改動 | 減少的等待 |
|---|---|
| 全文文字速覽先行 | 先取得整份教材的文字方向，不先渲染全部圖像 |
| 目前頁優先渲染 | 跳到第 70 頁時，不必等前 69 頁渲染完 |
| 首批最多 2 頁、後續最多 6 頁 | 降低第一批結果的等待，後續保留批次效率 |
| 分析結果先顯示 | 逐步講稿還在生成時，先讀已完成的本頁重點 |
| 索引與講稿獨立進行 | 已準備頁面先產生講稿，不等待全書索引及總覽 |
| 最多兩個模型請求 | 避免無限制併發；問答優先於尚未開始的背景工作 |
| 重用圖像與講稿快取 | 已有資產不重畫，已完成講稿不重跑模型 |
| 合併寫入與畫面更新 | 文字擷取保存最多每 250ms 合併一次，狀態通知 60ms 合併，串流畫面最多約每 100ms 更新，減少磁碟與公式排版負擔 |
| 已解壓程式＋桌面捷徑 | 日常開啟不必反覆解壓單檔程式，入口沿用既有資料目錄 |

進行中的模型請求不強制中斷。問題到達時若兩個請求都已開始，需等待一個容量釋出，之後優先於排隊背景工作。

## 實測範圍

同機、使用者提供的 191 頁數位系統教材，從 PDF Worker 啟動開始計時，優先頁設為第 70 頁：

- 全文文字取得：約 0.92 秒。
- 第 70 頁原頁圖像可用：約 1.17 秒。
- 所有 191 頁圖像完成：約 22.36 秒。
- 重用這批圖像的解析測試：約 0.71 秒，重新渲染頁數為 0。

這些是單次本機解析測試，不包含 OAuth、模型分析與講稿回應時間，不代表 AI 講解會在 1.17 秒內完成。改善的核心是讓第一頁工作約在原頁就緒時開始，不再先等待其餘圖像與全書模型分析。

## 準確性取捨

早期講稿根據當時可用的原頁、索引、術語及全文速覽生成。介面保存並顯示當時已詳細分析的頁數，模型也會被告知尚未完成全書核對。背景地圖擴充不自動刪除或覆寫既有講稿。

全書脈絡完成後，可手動使用「以完整教材脈絡更新這頁講解」。這會產生新的模型請求；不需要更新的頁面仍直接讀取舊紀錄。

## 後續可評估，尚未實作

1. **按需預先生成**：讓使用者選擇只預先準備附近頁面，減少未讀內容的運算與用量。
2. **分別量測分析與教學設定**：用固定教材比較不同設定的首段速度、公式正確性與用量，再決定是否分開選擇模型。
3. **背景講稿小批次合併**：減少請求往返，但需限制單批輸出，避免第一頁被長輸出拖慢或失敗時整批重做。
4. **增量資料庫保存與內容檢索**：教材與問答很多時改為增量資料庫，並只取回相關原頁，降低大型 JSON 保存及上下文成本。

以上需實測，不以犧牲原頁圖表、來源頁碼或不確定性標示換取表面速度。
