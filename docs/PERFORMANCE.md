# 效能設計、量測與限制

基準：**0.8.1**；更新日期：**2026-10-26**。排程細節見 [ENGINE.md](ENGINE.md)。本文件區分現有機制、歷史量測與未完成實驗。

## 1. 現行管線

| 機制 | 作用 | 邊界 |
| --- | --- | --- |
| 全文文字先行 | 先取得每頁文字方向，再派圖像工作 | 文字速覽不等於完整視覺核對 |
| 目前頁與後 9 頁優先 | 改善使用者跳頁後的等待 | 只改尚未派出的工作 |
| 索引首批最多 2 頁、後續最多 6 頁 | 縮短第一批等待，保留後續批次處理 | 每份教材同時只有一個索引 job |
| 索引與講稿分離 | 局部索引完成後即可讀對應講稿 | 來源圖像及該頁索引仍須就緒 |
| 單頁講稿動態補位 | 一頁完成即可派下一項合格工作 | 輸入未就緒、暫停或未授權時可有空槽 |
| 共用模型容量 | 所有教材預設合計 4，可調 1–6 | 不保證服務端線性加速或問答零等待 |
| PDF Worker | 每個 Loader 預設 2，可調 1–4 | 多教材各有 Loader，非全域 4 緒限制 |
| 密度與講解長度 | 減少簡單頁無關輸出 | 軟提示，不能保證模型遵循或答案正確 |
| 本機快取 | 已有圖像不重畫、完成講稿不重跑 | 中斷批次／頁面仍可能重做 |
| 合併通知與保存 | 文字擷取保存約 250ms、狀態通知約 60ms、串流呈現約 100ms 合併 | Engine 的完成快照仍直接保存整份教材 |
| 安裝版日常開啟 | 不必每次啟動可攜封裝的解壓程序 | 沒有此項的多次統計量測 |

## 2. AI 並行與 CPU 工作緒不同

AI 同時請求數控制 Provider 呼叫；PDF Worker 在本機處理 CPU 渲染。增加 Worker 不會直接提高模型端速度，提高 AI 容量也不會讓 PDF.js 的單頁渲染變快。

容量固定時，完成工作釋出槽位，Pool 立即派等待工作；Engine 約 30ms 後補登記後續工作。它不是 `Promise.all` 每 6 頁一輪。局部索引仍採小批次，因此觀察到等待不一定是講稿批次柵欄，也可能是下一批來源尚未就緒。

問題優先於排隊中的背景工作，但不搶占已在途呼叫，也沒有固定問答預留槽位。調低容量會等待現有工作完成，不因改設定取消它們。

## 3. 歷史本機 PDF 量測

### 0.3.0：同機 191 頁教材

使用獨立暫存資料夾，優先第 70 頁；單次依序量測，沒有多次取樣、硬體控制或完全冷磁碟快取。

| 工作緒 | 全文文字 | 第 70 頁圖像 | 全部圖像 |
| --- | ---: | ---: | ---: |
| 1 | 0.71s | 0.89s | 14.67s |
| 2 | 0.57s | 0.75s | 8.04s |

全圖時間約縮短 45%，約為 1.82 倍吞吐改善。這只描述該次 PDF 解析，不含 OAuth、模型推論、索引或講稿時間；不能推論 AI 也等比例加速。小文件可能因 Worker 建立與重複載入 PDF 而沒有相同收益。

### 0.2.0：更早的單次紀錄

同為 191 頁、優先第 70 頁：全文文字約 0.92s、該頁圖像約 1.17s、全圖約 22.36s。重用圖像時約 0.71s，重新渲染 0 頁。不同版本的單次數字只作歷史參考，不作嚴格 A/B 實驗。

原始紀錄見 [TESTING.md](TESTING.md) 與 [DEVLOG.md](../DEVLOG.md)；本次文件更新沒有重新量測。

## 4. 控制流程測試支持什麼

受控 Provider 測試支持多頁同時執行、亂序完成仍回到原頁、問題可超越排隊背景工作，以及快取不增加推論。PDF 測試支持共用派工、不重複頁碼、動態縮減仍完成、重用既有圖像。

0.7.1 的 35 次快速切換與縮放對照測試，重現舊版 Transport destroyed 並驗證修補；它是預覽生命週期回歸，不是 AI 速度基準。

目前沒有固定教材、固定真實模型的 p50/p95 推論延遲、用量或語義正確率統計。使用者對現況的滿意回饋是使用經驗，不轉換成準確率百分比。

## 5. 準確性與速度的取捨

早期講稿使用部分索引、術語與每頁前 100 個字串單位的文字速覽，另帶有限相關原頁。完整地圖後改用整合脈絡。早期輸入較早就緒，但仍可能缺少跨頁定義；覆蓋標記能追溯來源，不能自動保證正確。

動態補位若保持單次請求的模型、提示與來源不變，主要改變等待順序；但服務端限流、競爭及回答隨機性仍可能改變實際結果。因此不能只由排程形式宣稱品質必然相同或更好。

## 6. 後續實驗設計

| 比較 | 固定條件 | 主要指標 |
| --- | --- | --- |
| AI 容量 1 / 2 / 4 / 6 | 同教材、模型、來源、講解模式；記錄網路與時段 | 首份可讀、全書完成、問答 p50/p95、失敗／限流率、用量 |
| 動態補位與固定整輪 | 同工作耗時樣本及輸入；先以 Provider 替身驗證 | 槽位閒置率、完工時間、問題等待 |
| PDF Worker 1 / 2 / 4 | 同硬體、PDF、優先頁；區分冷／熱快取，多次重複 | 文字、首圖、全圖、CPU、記憶體 |
| 早期與完整上下文 | 固定人工標註跨頁樣本，分開控制模型 | 公式、符號、來源、補充標示、人工正確率 |
| 大書庫保存 | 固定頁數與對話量級 | JSON 寫入成本、切頁延遲、資料完整性 |

報告應區分真實模型與替身結果、首段與完整回答、冷啟動與快取；公布條件及未完成項目，不以模型自評取代獨立判定。

## 7. 尚未實作的候選優化

- 僅生成附近頁面的可選策略，減少未讀內容用量。
- 索引與講稿分別選模型；需以固定樣本驗證品質。
- 階層式摘要、token 預算與來源檢索，控制長文件輸入。
- 問答預留容量或 aging，降低背景飢餓與互動尾端延遲。
- 增量資料庫保存，避免大快照反覆寫入。

這些是待評估方向，不是目前已提供的功能。
