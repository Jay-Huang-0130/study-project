# 生成時間診斷

版本 0.10.0（診斷始於 0.9.4）。入口：設定 → 生成診斷。這是觀測功能，不改變模型、提示、頁碼派工、並行容量、重試或逾時政策，不新增模型呼叫。展開時每秒讀取診斷；收起後停止輪詢。

| 階段 | 起訖意義 | 能判斷的範圍 |
| --- | --- | --- |
| 容量等待 | 註冊請求至取得共用模型槽位 | 本機排程等待 |
| 啟動模型連線 | Provider 開始至 app-server 可用 | 本機服務啟動／連線 |
| 建立對話 | thread/start 送出至建立完成 | app-server 對話建立 |
| 等待啟動確認 | turn/start 送出至 RPC 回覆或 turn/started | 啟動握手尚未確認 |
| 等待首段文字 | 已接受但沒有可閱讀 agentMessage | 可能涵蓋模型處理及網路等，不能單獨歸因 |
| 接收模型內容 | 第一份非空 agentMessage 至請求結束 | 回覆階段 |

畫面「連線與建對話」合計前兩個服務階段；「送出至首段」從 turn/start 送出算起，包含啟動確認時間，因此各欄不能直接相加。無法觀測的欄位顯示 —，不補猜 0。第一段指可讀文字或結構化回覆，未將 reasoning 事件當作閱讀內容。模型回覆結束不等於教材後續結構驗證及保存完成，仍以講稿進度為準。

同一教材顯示本機文字／圖片、索引及講稿進度。正在準備本機資料且沒有模型請求時，可先確認前置資料；模型開始後再用各階段時間辨認等待位置。

ModelDiagnostics 使用單調時計與匿名隨機請求 ID，儲存教材內容雜湊、種類、附圖頁碼、模型、階段及時間。階段只能前進，晚到確認不把接收中改回等待；取消／完成後不再更新。紀錄集中在記憶體，清除最舊完成項目以保持常態上限 200 筆，進行中項目保留；畫面最多列 12 筆，進行中優先。

重開 App 會清空，無法回溯舊請求。使用者可手動匯出書庫根目錄 generation-diagnostics-時間戳.json，包含格式版本、App 版本、準備進度與請求時間；不含教材原文、圖片、講稿、問題、提示詞、圖片路徑、登入憑證或原始供應商錯誤。錯誤只分類為 timeout/network/quota/auth/other；檔案不會自動上傳。

IPC diagnostics / exportDiagnostics 使用既有主畫面來源檢查。原始碼：electron/diagnostics.ts、engine.ts、codex.ts、src/GenerationDiagnostics.tsx。觀察者例外會被隔離，不能讓生成失敗或重送。

0.10.0 的講稿顯示為「分批講稿」。附圖頁碼包含上下文參考，並非全部都要生成的目標頁；一個請求可能在尚未完成前已有多頁講稿保存，因此請求數與完成頁數不相同。AI 容量固定 1。

0.10.1 新增每次請求結束後的全域 5 秒間隔，列入「等待 AI 容量／容量等待」。等待期間 active 為 0、queued 大於 0 是正常狀態；不代表遠端限流。批次內每頁輸出不等待 5 秒。

## 0.10.2 錯誤事件與手動對照

每個請求另記錄最多 60 筆事件：建立對話、送出、RPC／開始確認、模型項目、推理活動、文字、錯誤與 willRetry、取消／中斷確認、解析、逐頁保存。連續文字／推理事件聚合成次數，僅留時間，不保存內容。錯誤只允許已知 codexErrorInfo 與有效 HTTP 狀態碼，不匯出 message、additionalDetails、URL、路徑、服務端 thread／turn 識別碼或 raw stderr。

收到 reasoning／item 活動且帶有效 turnId，表示本機已有該 turn，可前進等待文字；未收到 RPC 回覆不再被誤認成完全無活動。fatal error（willRetry=false）立即失敗，不繼續等待 8 分鐘。agentMessage commentary 不得混入講稿 JSON。這些是接收與觀測修補，不代表已查明特定上游等待的根因。

設定中的三個測試都需手動啟動，先暫停所有背景工作，共用 Engine 全域名額與 5 秒間隔。每個測試最多 120 秒，不自動重試。純文字只要求 OK；單頁測試送目前原頁與圖片，要求短講稿 JSON；直接對照沿用最近單頁輸入與模型，以獨立的 V2 請求／事件處理路徑繞過 CodexClient.generate 與講稿解析，但仍共用相同 app-server 程序與網路，因此不能排除該共用層的故障。測試不修改原教材講稿。

結果記錄最近 12 次測試，只保存模型、來源頁、狀態、格式檢查結果與 traceId；不保存測試提示與回覆。匯出會附 connectionTests，仍使用格式版本 1 的向後相容可選欄位。關閉面板不取消測試；可按取消測試，關閉程式也會取消。

本機服務統計包含收到訊息行數、無法解析行數、未配對 RPC 回覆數及安全通知類型計數。未配對可能是已取消 RPC 的晚到回覆，不應直接視為 bug。它是整個程序累計，不能代替單次請求追蹤。

判讀：明確收到 HTTP 429／rateLimitExceeded 才有服務回報的限流證據；收到 reasoning 代表有活動；收到文字但沒有保存須核對解析與結束事件。沒有任何回覆仍無法僅靠客戶端證明故障在遠端。成功／失敗對照是定位線索，非統計或責任判定。

協定依程式打包的 Codex 0.163.0 generate-json-schema 驗證，並對照官方文件 https://learn.chatgpt.com/docs/app-server 。

## 0.10.3 本機管道傳送確認

舊「App 已送生成指令」更名為「準備送出生成指令」，不再暗示已送達。新增開始寫入、背壓、管道寫入完成／失敗四種事件。完成是 Node Writable 的 write callback 成功，不等於 Codex 已讀取、接受或遠端已開始運算；RPC／turn 確認仍為獨立事件。

RpcWriter 對每個本機管道採 FIFO，檢查程序存活與 pipe writable/destroyed/ended/finished；寫入 false 代表背壓，保留該次寫入、不重送，後續等待 drain。監聽 error／close，涵蓋同步與非同步失敗；單筆等待寫入或寫入無進展超過 30 秒，令該傳送器失效、暫停相關工作並關閉失效的專用子程序，等待使用者重新確認連線，不自動重播模型請求。原有 8 分鐘模型期限與 5 秒請求間隔不變。

待回覆 RPC 顯示安全方法名、單調時計等待時間、等待寫入／正在寫入／背壓／已寫入等狀態。未知方法以 other 取代，不匯出參數或內容。暫停會撤銷尚未送出的排隊指令；若已開始寫入，不能假設 bytes 已撤回，仍保留精確 turnId 晚到中斷邏輯。已取消或已完成的 RPC 不會被晚到寫入 callback 重新建立。

程序與 stdout 事件綁定當次 child，舊 child 的關閉或資料不能影響新的連線。參考 Node 官方 Writable write callback／drain 行為：https://nodejs.org/download/release/latest-jod/docs/api/stream.html#writablewritechunk-encoding-callback 。

這次修補能攔截本機傳送失敗，但沒有證據能據此認定先前所有啟動等待都由此造成，亦不能以成功寫入排除 Codex 服務或遠端等待。
